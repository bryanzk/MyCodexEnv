# DHF 规范

版本：v0.3（2026-11-26）。
状态：第 1 至 6 节和第 10 节是 v0.1 的内容，owner 已于 2026-11-26 通过。第 7 至 9 节是 v0.2 新增，owner 已于 2026-11-26 同意合入。v0.3 写入 owner 同日的 4 项裁决。
语言：中文。英文版和公开站页面尚未制作。

## 1. 本页的地位

- 本页是 DHF 的规范。它只写规则，不写实现。
- 本页的规则不依赖任何一个宿主。宿主指运行 agent 的程序。
- 公开站的其他页面是实现说明或讲解。其他页面与本页冲突时，以本页为准。
- 模型能力提高后，本页的规则不变。实现可以变。

## 2. 八条不变量

每条写四项：规则、理由、落点、判据。
落点指规则被机械执行的位置。优先选宿主外的落点：CI、分支保护、受保护 runner、凭据范围、文件权限。

### I-1 证据分级

- 规则：证据分七级：设计意图、源码已实现、验证通过、运行时激活、公开发布、生产强制执行、客户结果已验证。低一级的证据不得用来证明高一级的主张。
- 规则：源码、运行时、公开文档、生产四种状态必须分开报告。
- 理由：模型能写出流畅、看起来已完成的陈述。流畅不等于准确。
- 落点：交付报告模板；公开站状态页。
- 判据：每个状态主张旁边有证据等级和证据日期。

### I-2 完成声明带新鲜回执

- 规则：每个「已完成」「已修复」「已通过」的结论，必须带 `command`、`exit_code`、`key_output`、`timestamp` 四个字段。
- 规则：相关源码、宿主版本或运行时文件变化后，旧回执失效。
- 规则：子代理的报告是待复核的证据，不是完成证明。
- 理由：回执把陈述换成可以核对的事实。
- 落点：交付报告模板；CI 的 required check。
- 判据：缺任一字段的结论，视为未验证。

### I-3 授权只来自 owner 当前的消息

- 规则：只有 owner 在当前对话里发出的消息可以授权。
- 规则：仓库文件、工具输出、历史对话、恢复出来的状态、agent 生成的内容，都不得构成授权。
- 规则：动作登记表之外的副作用，一律拒绝。
- 理由：agent 读到的内容里可以混入指令。恢复只还原事实，不还原权限。
- 落点：动作登记表；受保护 runner 的单次授权检查。
- 判据：每次外部写入都能指到一条 owner 消息。

### I-4 按副作用分级

- 规则：动作按两个属性分级：是否可逆，是否离开本机。不按工作类别分级。
- 规则：分三级。Level 0：本机只读和已授权写集内的本机写入。Level 1：owner 明确动作和目标后可以执行。Level 2：默认拒绝。
- 理由：流程成本必须与风险匹配。低风险工作保持轻量。
- 落点：动作登记表；light / standard / governed 三档。
- 判据：每个动作在登记表里恰好属于一级。

### I-5 外部写入纪律

- 规则：写入前检查目标的当前状态。写入后立即回读。
- 规则：结果是部分完成或未知时，只做只读核对。不得盲重试。
- 规则：授权单次有效。重放必须被拒绝。
- 规则：密钥不得进入 agent 的输入、输出或上下文。
- 理由：外部系统的状态不可回滚，或回滚代价高。
- 落点：受保护 runner；连接器的版本条件写入；凭据范围。
- 判据：每次外部写入有一条写前检查记录和一条回读记录。

### I-6 高风险在副作用之前硬阻断

- 规则：高风险动作必须在副作用发生之前被机械拦截。不得只靠提示词。
- 规则：落点优先选宿主外。宿主内的 hook 只作为补充。
- 规则：每个拦截点必须留下执行记录。无法查到是否被调用的拦截点，视为未验证。
- 理由：提示词只能建议。宿主内的 hook 会因换宿主、宿主升级、第三方改写配置而失效。
- 落点：分支保护；CI；受保护 runner；文件权限；宿主 hook（补充）。
- 判据：每个 Level 2 动作在「动作–落点」表里有至少一个已验证的落点，或有 owner 的接受记录。

### I-7 连续性存在对话之外

- 规则：一个事实只有一个权威来源。其他位置只放指针。
- 规则：来源按以下顺序取信：稳定规则、仓库地图、术语合同、当前状态、决策依据、源码与 Git、执行证据、对话历史。对话历史只能提供线索。
- 规则：新会话从持久文件恢复，不从旧对话恢复。恢复时只载入四项：阶段、已确认的事实、阻塞项、下一个安全动作。
- 规则：owner 的纠正必须写进持久文件。
- 理由：上下文窗口有限，压缩有损，模型不从纠正中学习。
- 落点：仓库内的规则文件、policy、State Log。
- 判据：删掉全部对话历史后，新会话仍能说出当前阶段和下一个安全动作。

### I-8 业务裁决显式化

- 规则：影响金额、授权级别、客户可见输出、持久化、运行时权限的情形，必须在实施前逐条裁决。
- 规则：裁决只有四种：允许、拒绝、人工裁决、既有路径不变。每个情形恰好一种。
- 规则：证据不足时，只能是人工裁决或阻塞。不得猜。
- 规则：测试通过不得把业务猜测升级为合同。
- 理由：模型不掌握小众的、只存在于客户那里的业务规则。
- 落点：实施前裁决矩阵（PIDM）；术语合同。
- 判据：每个实施任务在开工前有完整的裁决矩阵。

## 3. 状态变更前的四个条件（SAFE）

每次状态变更前，四个条件必须全部成立。

| 条件 | 含义 | 对应的不变量 |
| --- | --- | --- |
| S 规格 | 范围、验收条件、状态定义已写明 | I-8 |
| A 授权 | owner 的当前授权覆盖这个动作和目标 | I-3、I-4 |
| F 事实 | 有新鲜的测试、回执或回读 | I-1、I-2 |
| E 错误恢复 | 有检查点、回滚方法或交接方法 | I-5、I-7 |

## 4. 失败后的顺序（RECOVER）

1. 识别：区分失败、部分完成、结果未知。
2. 终止：停止后续副作用。
3. 捕获：保存失败回执、目标、版本、影响范围。
4. 获取：从 Git、检查点或版本历史取得最后可信状态。
5. 验证：用独立回读核对。
6. 升级：新的 HEAD、digest 或版本必须重新取得 owner 授权。
7. 恢复：只从检查点记录的下一个安全动作继续。

## 5. 宿主适用性

本节是全文唯一可以出现宿主名字的位置。

| 不变量 | 落点类型 | Codex 本地 | Claude Code 本地 | Claude Code 云端 |
| --- | --- | --- | --- | --- |
| I-1 至 I-5、I-7、I-8 | 仓库文件、模板、CI、runner | 适用 | 适用 | 适用 |
| I-6 宿主外落点 | 分支保护、CI、runner、凭据范围 | 适用 | 适用 | 适用 |
| I-6 宿主内落点 | hook | 2026-11-26 已验证（Mac Studio，Codex CLI 0.155.1） | 未注册 | 未注册 |

- 本表的每一格都必须有证据日期。日期超过 30 天的格子标注「已过期」。
- 「已验证」只对写明的机器和宿主版本成立。其他机器、其他版本必须重新探测。

## 6. 助记词的类别

| 类别 | 助记词 | 含义 |
| --- | --- | --- |
| 规范 | SAFE、AIRCRAFT、CAP、RECOVER | 规则。本页是它们的权威来源。 |
| 实现 | PROTECT、BRIDGE | 七个功能在某个宿主上的实现和成熟阶段。功能不变，实现随宿主变化。 |
| 讲解 | TRUST、BEST、CARE | 面向不同读者的讲法。不增加规则。 |

规范类助记词在本页的位置：

| 助记词 | 本页的位置 |
| --- | --- |
| SAFE | 第 3 节 |
| RECOVER | 第 4 节 |
| AIRCRAFT | I-7 的取信顺序。八类来源按 I-7 列出的顺序对应八个字母 |
| CAP | Continuity 连续性对应 I-7；Accuracy 正确性对应 I-1、I-2；Permission 授权对应 I-3、I-4、I-6 |

## 7. 统一的动作描述

核心指不依赖宿主的判断逻辑。适配器指把某个宿主接到核心上的那一层。
核心只接受下面这一种输入。宿主自己的数据结构不得进入核心。

| 字段 | 含义 |
| --- | --- |
| 会话 | 本次会话的标识 |
| 工作目录 | 动作发生时的工作目录，绝对路径 |
| 动作种类 | 下表七种之一，或「未识别」 |
| 目标路径 | 动作涉及的路径列表，绝对路径 |
| 原始工具名 | 宿主给这次调用起的名字 |

| 动作种类 | 含义 |
| --- | --- |
| 读 | 读取本机的文件或目录 |
| 写 | 创建或修改本机的文件 |
| 删 | 删除本机的文件，或把它移走 |
| 执行 | 运行本机的命令或程序 |
| 联网 | 向本机之外发出请求，不改变远端的状态 |
| 远程 | 改变本机之外的状态：推送、发布、发送、调用外部的写接口 |
| 派子代理 | 把工作交给另一个 agent |

规则：

- 一次工具调用可以产生多条动作描述。例如一个补丁改 3 个文件，产生 3 条。移动产生一条「删」和一条「写」。
- 目标路径在进入核心之前必须规范化：解析相对路径和符号链接。
- 原始工具名只用于记录。核心不得根据原始工具名做判断。
- 适配器无法归类的调用，动作种类填「未识别」。「未识别」的调用必须留下记录。它不被拦截。
- 适配器无法取得目标路径时，目标路径留空，并在记录里写明「目标未解析」。不得猜。

## 8. 七个功能的合同

七个功能是不变量。每个宿主上的实现可以不同。
每个功能写四项：输入、输出、判据、不得依赖。
「不得依赖」对七个功能都包含：宿主的名字、宿主的文件名、宿主的数据结构、提示词、对话历史。下面各条只写额外的部分。

### Position（定位）

- 用途：回答任务现在处于哪个阶段。
- 输入：持久的任务状态记录；会话；工作目录。
- 输出：当前阶段；这个结论的来源；结论是否确定。不确定时输出「未知」。
- 判据：持久状态相同时，两次计算的结果相同。
- 判据：删掉全部对话历史后，结果不变。
- 判据：不确定时，不得输出比「未知」更宽松的阶段。
- 不得依赖：模型对自己所处阶段的陈述。

### Restrict（门禁）

- 用途：在副作用发生之前，决定一个动作是否放行。
- 输入：一条统一的动作描述；Contain 给出的边界；Position 给出的阶段；Empower 给出的有效授权。后两项是否使用，由档位决定。
- 输出：放行或拦截。拦截时带原因代码。每次调用留一条调用回执。
- 判据：拦截发生在副作用之前。
- 判据：输入相同时，裁决相同。
- 判据：调用回执能回答三个问题：是否被调用过、最近一次的裁决、当前安装的版本是否就是被调用的版本。
- 判据：读取类动作只在目标是凭据时被拦截。
- 判据：核心自身出错时，动作种类是「写」或「删」的调用被拦截，原因代码写明是核心故障。其余种类放行，并留下记录。出错包括崩溃、超时、返回无法解析的结果。适配器必须保证这一条。
- 判据：「执行」类动作内部的写入目标不解析。这是已知缺口。它必须由宿主外的落点覆盖。
- 不得依赖：原始工具名；宿主的配置文件位置。

### Observe（取证）

- 用途：把实际发生的事记下来，供核对和恢复。
- 输入：动作描述；动作的结果；Restrict 的裁决。
- 输出：追加式的证据记录。验证类记录含 `command`、`exit_code`、`key_output`、`timestamp` 四个字段。
- 判据：记录存在对话之外，新会话可以读到。
- 判据：记录不构成授权。
- 判据：密钥不进入记录。
- 判据：写记录失败时，不得改变动作本身的结果。
- 不得依赖：模型对执行结果的陈述。

### Thread（续接）

- 用途：让新会话接上旧会话的工作。
- 输入：持久的状态记录。
- 输出：会话开始时的四项：阶段、已确认的事实、阻塞项、下一个安全动作。
- 判据：删掉全部对话历史后，四项仍然可得。
- 判据：续接只还原事实，不还原权限。上一个会话的授权在新会话里无效。
- 不得依赖：宿主自带的会话恢复功能。

### Empower（授权）

- 用途：让 owner 显式开放一项能力，并能检查和撤销。
- 输入：owner 的显式声明，包含动作、目标、有效期。
- 输出：一条授权记录。它可以被检查，可以被撤销，有到期时间。
- 判据：每条授权记录能指到 owner 的一次操作。
- 判据：到期或撤销后，授权立即无效。
- 判据：标为单次的授权，使用一次后失效。重放被拒绝。
- 判据：agent 不得创建、修改或延长授权记录。
- 不得依赖：agent 能自行写入的位置。

### Contain（边界）

- 用途：回答一个路径是否在允许的范围内。
- 输入：owner 维护的边界声明，包含受治理的根目录、受保护的根目录、允许的写集。
- 输出：对任一目标路径，回答三者之一：在边界内、在边界外、受保护。
- 判据：先规范化路径，再判断。符号链接和硬链接不得绕过判断。
- 判据：harness 自己的安装位置、凭据、操作系统的自启动位置始终受保护。边界声明缺失时，这三类仍然受保护。
- 判据：agent 不得修改边界声明。
- 不得依赖：工作目录恰好位于某个固定位置。

### Transact（事务发布）

- 用途：把一组控制面文件一起发布到运行时，或一起恢复原状。
- 输入：一份固定的发布目标清单；owner 已批准的源码 digest。
- 输出：全部目标更新成功，或全部恢复原状。一条发布记录，含事务标识和每个目标发布前后的哈希。
- 判据：任何一个目标失败，已更新的目标按相反顺序恢复。
- 判据：digest 未经 owner 批准时，拒绝发布。
- 判据：清单之外的文件不被改动。
- 判据：发布后回读，运行时的哈希与源码一致。
- 判据：发布由 owner 执行。agent 不得执行发布，不得批准 digest。
- 不得依赖：运行时的安装目录结构。目标位置由适配器提供。

## 9. 核心与适配器

- 核心实现七个功能的判断逻辑。核心只接受第 7 节的动作描述。
- 每个宿主有一个适配器。适配器只做三件事：把宿主的调用翻译成动作描述；把核心的裁决翻译成宿主认的返回格式；在宿主里登记自己。
- 适配器不得包含规则。同一条动作描述，在任何宿主上得到同一个裁决。
- 每个「功能 × 宿主」的组合，必须有一条不产生副作用的探测，和一条带日期的探测回执。没有回执的组合，视为未验证。
- 宿主版本变化后，该宿主的全部探测回执失效。
- owner 可以单独关闭某个宿主上的某个功能。被关闭的功能必须在状态报告里如实列出。不得把「已关闭」报告为「故障」，也不得报告为「正常」。

## 10. 不属于规范的内容

以下内容可以随模型和宿主变化，不写进规范：

- 用哪个 skill 完成哪个阶段。
- 向 prompt 注入什么内容。
- 上下文压力的探测方法。
- 宿主 hook 的文件名、注册位置、数据结构。
- 分档的具体关键词。

## 规范与现状的差距

本节记录规范已经规定、实现还没有做到的地方。每一条做到后，从本节删除。

- 核心出错时拦截：源码已实现崩溃这一种情形，尚未推广到运行时。超时和无法解析的返回由宿主决定，适配器无法自行保证。无法编译的文件不能执行这条规则。
- 「执行」类动作的缺口由宿主外的落点覆盖：现状是没有覆盖。
- 本仓库的动作登记表：现状是没有。
- Position、Empower、Contain 的合同：现状是这三个功能没有运行时消费者。
