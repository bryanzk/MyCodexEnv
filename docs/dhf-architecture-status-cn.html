当前架构

1 · Host 与 runtime hooksSessionStart：naming → session_bearing.py。UserPromptSubmit：compaction_probe.py → dhf_preprompt.py，后者在参考机器上已被 owner 关闭。PreToolUse：harness_guard.py。PostToolUse：harness_observer.py。在 Claude Code 上，守卫是装在仓库里的一个 PreToolUse hook。
2 · 通用 router 与 repo adapter通用 dispatcher 先处理 opt-out，再 lazy delegate 已知仓库，最后按生命周期阶段路由显式 DHF 工作。项目路径、fixture、命令与业务边界留在 repo-specific adapter。
3 · 生命周期与专门工作流research、requirements、planning、development、validation、review、ship、handoff 八个标准阶段选择规划、TDD、QA、安全、发布、文档或确定性 helper。
4 · 耐久治理与证据harness_recover.py、harness_checkpoint.py、harness_ledger.py、harness_transition.py、harness_eval.py、schemas、状态日志和四字段验证收据让任务可恢复、可审计。
5 · 分发边界codex/ 是仓库源码，~/.codex 是机器运行时。推广是显式的、有目标清单的、可回滚的，并且要 owner 先批准源码 digest。Claude Code 的适配器则跟着仓库走。公开文档和将来的独立核心发布，是各自独立的发布通道。

验证边界

原则：历史绿灯永远不能证明当前运行时。任何部署或环境变更之后，DHF 都会重新执行源码测试、逐文件一致性核对与环境验证,通过后才声明完成。

每个完成声明都以新鲜、可机器核验的验证凭据为支撑,而不是依赖记忆或过去的状态。
