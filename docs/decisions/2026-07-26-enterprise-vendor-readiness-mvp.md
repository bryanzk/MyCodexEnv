# Enterprise Vendor Readiness MVP 决策记录

- 日期：2026-07-26
- 状态：已记录
- 来源：[ChatGPT 共享对话](https://chatgpt.com/share/6a66a89e-dcfc-83ea-914f-09cf5dbe1013)
- 主题：面向北美中小企业的供应商准入准备度扫描、报告与付费服务

## 1. 核心产品定位

产品不宣称通过外部扫描判断企业是否“符合 SOC 2”或“通过 ISO 27001”，也不签发合规证书。

产品定位为：

> 扫描供应商的外部安全状态，判断其进入企业采购流程的基本准备度，并指出仍缺少哪些内部证据、整改动作与验证材料。

核心商业价值不是提供更多技术扫描项，而是把公开安全信号转化为：

- 可能影响企业采购的阻塞项；
- 采购方可能继续追问的问题；
- 供应商需要补齐的证据；
- 可执行的整改优先级；
- 整改后的复验记录。

## 2. 产品分层

### 免费产品

名称：**External Vendor Readiness Snapshot**

中文：外部供应商准备度快照。

免费报告用于建立可信度，回答：

- 是否真的观察到问题；
- 问题与企业采购准入有什么关系；
- 扫描方是否在使用恐惧营销。

免费报告必须：

- 明确只检查公开网站、DNS、Cookie、第三方服务和公开政策页面；
- 明确没有登录、利用漏洞、访问内部系统或实施侵入式测试；
- 先展示两个正面信号，再完整展示一个高可信重点发现；
- 给出观察时间、资产、证据、置信度、业务含义和一个整改方向；
- 展示其余发现的真实数量和标题，不制造虚假紧迫感；
- 明确列出外部扫描无法验证的内部控制；
- 使用私密、不可被搜索引擎索引的报告链接；
- 提供更正或删除入口；
- 只保留一个主要 CTA：`Get the complete Vendor Readiness Assessment`。

### 付费产品

名称：**Enterprise Vendor Readiness Assessment**

中文：企业供应商准入准备度评估。

付费报告用于支持决策、整改和验证，必须包含：

- Executive Procurement Summary；
- 完整发现列表及证据；
- 技术严重程度、采购影响和修复工作量的独立评级；
- 采购安全问卷映射；
- 内部证据请求清单；
- 按商业优先级组织的整改路线图；
- 人工审核；
- 一次整改后复验；
- 可下载的完整报告。

付费报告不应命名为 `Full Security Audit`，因为仅凭外部扫描和有限的内部输入无法形成完整安全审计。

## 3. 免费与付费边界

总原则：

> 免费报告出售可信度；付费报告出售决策、整改和验证。

免费版不应故意隐藏重点发现，也不应只给一个缺少证据的安全分数。付费价值来自完整上下文、采购影响映射、内部证据收集、整改顺序、人工判断和复验，而不是简单增加扫描数量。

## 4. 证据与结论模型

所有结论使用以下证据状态：

| 状态 | 含义 |
| --- | --- |
| `Observed` | 扫描直接观察到 |
| `Declared` | 企业公开声明 |
| `Verified` | 由证书、报告或正式材料支持 |
| `Unknown` | 外部无法验证，需要内部材料 |

所有发现至少区分：

- 技术风险；
- 采购影响；
- 修复工作量；
- 置信度；
- 证据状态。

不得把网站上的 SOC 2 或 ISO 27001 声明直接标记为已验证。需要进一步确认报告或证书的真实性、法律实体、范围、有效期、审计期间、意见与例外。

## 5. MVP 交付方式

第一阶段采用人工审核的 **Concierge MVP**，不优先开发完整 SaaS。

建议流程：

```text
收集公开信号
→ 规则引擎生成初步发现
→ 人工确认重点发现并删除误报
→ 生成私密免费报告
→ 发送合规的定向邮件
→ 客户付费
→ 客户填写简短业务与数据问卷
→ 人工完成完整评估
→ 整改后复验
```

前期优先验证：

- 哪类企业会打开报告；
- 哪类发现最能产生购买意愿；
- 正确收件人是谁；
- 客户愿意为什么内容付费；
- 客户更需要报告、整改服务还是采购问卷支持。

## 6. MVP 扫描边界

### 免费版可自动化

- 网站配置：HTTPS、TLS、HSTS、CSP、Cookie 属性、安全响应头、混合内容和基础错误泄露；
- 邮件与 DNS：SPF、DMARC、MX、域名与证书状态、`security.txt`；
- 隐私与透明度：Privacy Policy、Cookie Policy、Terms、Security 页面、Trust Center、Subprocessor 页面和数据请求入口；
- 第三方服务：分析、广告像素、聊天、Cookie Consent、CDN、支付和嵌入资源；
- Assurance Signals：SOC 2、SOC 3、ISO 27001 的公开声明、证书编号、审计期间、认证机构和 Trust Center 入口。

### MVP 暂不包含

- SQL 注入或漏洞利用验证；
- 密码猜测、登录绕过和账户攻击；
- 大规模端口扫描或高强度目录枚举；
- API 模糊测试；
- 认证后扫描；
- DoS 类型测试；
- 未经明确授权的主动安全测试；
- 自动给出“合规 / 不合规”结论；
- 自动签发 SOC 2、ISO 27001 或通用合规证书。

公开、低影响检查与获得授权后的主动安全测试必须严格分开。

## 7. 严重发现处理

公开密钥、暴露数据库、敏感文件、明显可利用的高风险漏洞或客户数据泄露，不得作为付费销售筹码。

这类发现必须从销售流程中分离：

- 限制披露细节；
- 通过正式安全联系人负责任披露；
- 提供足够的验证信息；
- 不把修复信息作为立即付款条件；
- 待安全事件处理后，再单独讨论商业服务。

免费/付费边界只适用于常规安全卫生、采购准备度与证据差距。

## 8. 价格与套餐

MVP 只设置一个付费方案：

**Enterprise Vendor Readiness Assessment**

- 测试价格：USD 299–499，一次性；
- 包含完整外部评估、简短业务与数据问卷、人工验证、采购影响映射、整改路线图、一次复验和完整可下载报告。

MVP 暂不设置 Basic / Pro / Premium 多层套餐、复杂月度订阅、按漏洞数量收费或按页面数量收费。

持续监控、Trust Center 和安全问卷自动化留作后续订阅产品候选。

## 9. 首批目标客户

优先：

- B2B SaaS；
- 网站提供 Enterprise、API 或客户门户；
- 服务金融、医疗、保险、政府或大型企业；
- 已有 Security 或 Trust 页面；
- 公开声明 SOC 2 或 ISO 27001；
- 接收客户文件或个人信息；
- 正在招聘 Security、Compliance 或 Enterprise Sales；
- 网站提及 vendor、partner 或 procurement。

暂不优先：

- 仅展示地址和电话的本地商家；
- 不处理客户数据的小型服务企业；
- 没有企业采购场景的个人网站；
- 没有登录、表单或数据服务的静态宣传网站。

## 10. 外联边界

外联邮件包含付费服务入口，应按商业电子邮件管理，不能包装成纯安全通知。

外联必须：

- 使用准确、克制的标题和发件人信息；
- 明确扫描范围、方法和限制；
- 不使用“紧急”“严重失败”等恐惧营销措辞；
- 不公开客户问题；
- 包含适用的实体地址、联系信息和退订机制；
- 记录联系人来源、发现时间、公开证据、业务相关性、禁止营销声明和退订状态；
- 在加拿大市场使用“显著公开”作为默示同意前，验证地址来源、角色相关性和是否存在拒绝非请求邮件的声明；
- 不把购买的批量联系人名单作为加拿大市场的主要获客来源。

正式外联前需要对目标地区、收件人和当时适用的 CASL、CAN-SPAM 及隐私要求做法律复核。

## 11. 数据结构

每个 Finding 至少包含：

```text
finding_id
company_id
asset
category
title
observed_at
observation
evidence
confidence
technical_severity
procurement_impact
framework_reference
remediation_summary
remediation_detail
estimated_effort
recommended_owner
visibility_level
review_status
rescan_status
```

`visibility_level` 使用：

- `FREE_FULL`
- `FREE_SUMMARY`
- `PAID_ONLY`
- `RESPONSIBLE_DISCLOSURE_ONLY`

外联记录至少包含：

```text
recipient_email
recipient_role
source_url
date_discovered
publication_evidence
no-solicitation_status
reason_message_is_role_relevant
email_sent_at
unsubscribe_status
```

## 12. MVP 模块

第一版只包含五个模块：

1. **Passive Scanner**：检查网站、DNS、Cookie、第三方服务和公开政策。
2. **Finding Rules Engine**：把技术发现映射为安全影响、采购影响和整改方向。
3. **Human Review Console**：发送前确认结果、删除误报并选择重点发现。
4. **Private Report Page**：展示免费内容、隐藏付费内容，并支持更正、删除和付款。
5. **Paid Report Generator**：整合客户问卷、完整发现、整改路线和复验结果。

## 13. 成功指标

漏斗按以下顺序记录：

```text
合规发送数量
→ 私密报告访问率
→ 重点发现查看率
→ 完整报告 CTA 点击率
→ 支付页面到达率
→ 实际购买率
→ 整改执行率
→ 复验完成率
```

不要只使用邮件打开率判断产品是否成立。

## 14. 后续验证事项

以下内容仍需通过真实客户实验或专业复核确认，不能当作已验证事实：

- USD 299–499 的可接受价格区间；
- 最有效的重点发现类型与邮件标题；
- 免费报告到付费报告的实际转化率；
- 客户对报告、整改服务、问卷支持三者的付费偏好；
- 不同州、省、行业及数据类型对应的法律与合同要求；
- SOC 2、ISO 27001、PCI DSS、HIPAA、GLBA、PIPEDA、CCPA/CPRA 等要求在具体客户场景中的适用性。

## 15. 一句话原则

> 免费版给出足够多的事实，让客户相信；付费版给出足够完整的路径，让客户行动。
